# Simulator validation against a real Cloud Run service

A service with known settings (1 vCPU, 512 MiB, concurrency 4, min 0, max 10, request-based billing; `rs-target`) was driven with scripted bursts after scaling to zero. Cloud Monitoring's measurements for the window are compared with the simulator's prediction for the same arrival schedule and settings, using the service's own measured latency and startup-latency quantiles as inputs (no fitting to the outcome). Generated by `validation/report.py`; raw numbers in `validation/comparison-*.json`.

## Pattern A (used to choose the model's routing, scale-out and billing assumptions)

Bursts (start s, requests, length s): [[0, 40, 3], [180, 120, 6], [420, 240, 8], [660, 80, 4]]; each request waits 400 ms; 480 sent, 478 succeeded, 2 failed.
Measured startup latency quantiles p5/p50/p95/p99 (s): [1.31, 14.22, 16.65, 16.87].

| metric | measured | predicted | error | note |
|---|---|---|---|---|
| Requests | 480 | 480 | +0% | count |
| Instances started | 11 | 10 | -9% | count |
| Peak instances | 9 | 10 | +11% | count |
| Server-side p50 latency (ms) | 394 | 414 | +5% | warm service time |
| Client p95 latency (ms) | 2283 | 474 | -79% | includes cold-start waits |
| Client p99 latency (ms) | 15686 | 14710 | -6% | includes cold-start waits |
| Billable instance-seconds | 149 | 172 | +15% | request-based billing |
